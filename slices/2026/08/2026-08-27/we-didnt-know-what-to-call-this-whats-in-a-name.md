# H0 — THE CRAZY SEED

Preserve the seed verbatim:

> **We didn't know what to call this: What's in a name?**

Literalized too quickly, that question can smuggle several incompatible claims:

```text
NAME CONTAINS ESSENCE
NAME IS ONLY AN EMPTY LABEL
NAMING CREATES THE THING
NAME GUARANTEES IDENTITY
NAME GRANTS ACCESS
NAME GRANTS AUTHORITY
NAME CARRIES THE WHOLE WORLD
```

ALEX refuses all seven as defaults.

The question has to be decomposed first.

---

# PEEL 1 — THE NAME IS NOT THE THING

The boring control is strong and old.

Philosophy of language has spent a very long time arguing about how proper names refer. Descriptivist theories connect reference to identifying descriptions; causal/direct-reference families deny that the name's semantic work requires the name to contain a descriptive miniature of the bearer.

The exact philosophy remains contested.

But one conclusion is enough for this slice:

> **A useful theory of names does not need the word to contain the properties of the thing.**

The Stanford Encyclopedia of Philosophy's current entries on **Names** and **Reference** preserve this dispute and its major families:

- https://plato.stanford.edu/entries/names/
- https://plato.stanford.edu/entries/reference/

That gives the first anti-collapse law:

```text
NAME
!=
DESCRIPTION OF EVERYTHING TRUE ABOUT REFERENT
```

And therefore:

```text
NAME
!=
ESSENCE
```

This is not a new eCODE discovery.

It is the boring floor beneath the experiment.

---

# PEEL 2 — SHAKESPEARE'S ROSE IS ONLY HALF THE TEST

The phrase that named this slice already carries a famous ancestor.

In *Romeo and Juliet* 2.2, Juliet asks:

> “What's in a name?”

and argues that the rose would retain its sweetness under another word.

The Folger text makes the surrounding structure even more useful than the isolated quotation:

```text
'Tis but thy name that is my enemy.
Thou art thyself, though not a Montague.
...
What's in a name?
...
Romeo, doff thy name.
```

Source:
https://www.folger.edu/explore/shakespeares-works/romeo-and-juliet/read/

Juliet's local claim is almost a clean identity control:

```text
CHANGE NAME
!=
CHANGE INTRINSIC PERSON
```

But the scene simultaneously contains the counterpressure.

`Montague` matters enormously.

Not because the letters **contain** Romeo's body or essence.

Because a receiving social world resolves the name into an inherited relational field:

```text
MONTAGUE
  ↓ received inside Verona's social constitution
family relation
feud relation
friend/enemy classification
expected loyalties
risk
consequence
```

So the rose test and the feud test can both be true:

```text
NAME != ESSENCE

while

NAME CAN ACTIVATE RELATIONAL CONTEXT
```

That is a better answer than either extreme.

The name does not have to change the rose to change what happens around the rose.

---

# PEEL 3 — A NAME CAN GIVE RELATION SOMEWHERE TO ACCUMULATE

This is where the external research became unexpectedly close to the current project question.

Robin Jeshion argues that proper names do more than merely contribute reference. They can function as markers of individuality and as labels for mental files through which information, thought, plans, and significance become organized around an individual.

Especially relevant here: the account explicitly discusses names helping organize thought about epistemically remote individuals and even individuals not yet in existence.

That does **not** prove an eCODE primitive.

But it gives a documented cognitive neighbor for something the Slice titles appear to be doing:

```text
NAME COINED
  ↓
A STABLE FILE / HANDLE EXISTS
  ↓
LATER INFORMATION CAN ACCRETE
  ↓
THE REFERENT BECOMES EASIER TO RE-ADDRESS
```

Source road:

Robin Jeshion, “The Significance of Names,” *Mind & Language* 24.4 (2009), 370–403.
DOI: https://doi.org/10.1111/j.1468-0017.2009.01367.x

A related empirical critique of strong descriptivism argues that competent name use does not require possession of the rich identifying descriptions some theories assume:

Eduardo García-Ramírez & Marilyn Shatz, “On Problems with Descriptivism: Psychological Assumptions and Empirical Evidence,” *Mind & Language* 26.1 (2011), 53–77.
DOI: https://doi.org/10.1111/j.1468-0017.2010.01410.x

This suggests a candidate distinction:

```text
THE NAME DOES NOT CONTAIN THE FILE.
THE NAME HELPS US KEEP FINDING THE FILE.
```

And once the file exists, history can gather there.

---

# PEEL 4 — BUT NAMING IS NOT MAGIC

The dangerous version now becomes obvious:

> If names organize thought, then naming creates reality.

No.

Labels and language can influence categorization, expectation, attention, and social scripts in some domains. But effects are conditional, domain-specific, and falsifiable.

A useful null comes from recent cross-linguistic work on taste. Bylund, Samuel, and Athanasopoulos tested whether language-specific food labels changed taste perception and found no evidence for the expected label-driven perceptual difference in that experiment.

Source:

Emanuel Bylund, Steven Samuel & Panos Athanasopoulos, “Crosslinguistic Differences in Food Labels Do Not Yield Differences in Taste Perception,” *Language Learning* 74.S1 (2024), 20–39.
DOI: https://doi.org/10.1111/lang.12641

So preserve:

```text
NAMING CAN SHAPE ATTENTION / CATEGORIZATION / EXPECTATION
!=
NAMING NECESSARILY CHANGES THE UNDERLYING THING
!=
NAMING NECESSARILY CHANGES PERCEPTION
!=
NAMING CREATES REALITY BY FIAT
```

This is essential for the Static Collective because our names are deliberately generative.

`STORYSHIP`, `IRON LUNG`, `SEEDBANK`, `3rdi`, `PEEL`, `LEEP`, `MEMENTO`, `THE HAUNTED TOASTER`—these names can become excellent compression handles.

That does not make the metaphors literal anatomy.

```text

```

```text

is not automatically lawful.

A name can generate forward.

Today's decoder work adds another useful constraint:

```

but:

```text
PROJECTION != EVIDENCE != AUTHORITY != CONSEQUENCE
```

So whatever a name becomes in a receiving world, the projection does not crown itself true.

# PRESSURE RESULT — WHAT BROKE

The following claims do not survive:

## `NAME = ESSENCE`

Same referent can survive renaming, translation, transliteration, nickname, title change, or other form change.

## `NAME = UNIQUE IDENTITY`

Different referents can share the same name.

## `NAME = DESCRIPTION`

A speaker can competently use a name without carrying a complete identifying description of its bearer.

## `NAME = AUTHORITY`

The earlier Sceva control already kills this inside the project research lane.

## `NAMING = CREATION`

Naming can organize later cognition and behavior without creating the referent or universally changing perception.

## `LATER NAME = EARLIER ANCESTRY`

A later label may become generative going forward. It does not retroactively cause the history that preceded its coinage.

## `NAME = EMPTY NOTHING`

This also fails.

Names can stabilize reference, mark individuality, coordinate communication, organize mental files, carry social classification, accumulate reception history, and become persistent handles for future action.

The word may be small.

Its relational consequences need not be.

---

# WHAT SURVIVED

The strongest survivor is:

> **A name is a small, socially stabilized carrier that can make a referent re-addressable and give later relation somewhere to accumulate.**

Or more formally:

```text
NAME INSTANCE
=
FORM
+
BINDING EVENT / CLAIM
+
REFERENT SCOPE
+
RECEIVING CONTEXT
+
USAGE / TRANSFORMATION HISTORY
```

The string alone is not the whole name-event.

For any useful continuity claim, preserve at least:

```text
what form was used?
who or what was being named?
when was the binding made?
by whom / in what community?
what earlier names or aliases existed?
what later relations accumulated under it?
what changed when the name changed?
what did NOT change?
```

This is almost embarrassingly close to ordinary provenance practice.

Which is good.

ALEX is supposed to kill the need for mystical inflation before preserving the weird survivor.

# THE STRANGER SURVIVOR — A NAME MAY BE AN ADDRESSABLE ATTRACTOR

“Address” alone is not quite enough for the Slice-title phenomenon.

An address helps us find something already there.

But a project title can be coined **before the full thing exists**.

Once coined, the name can become a place where future structure gathers:

```text
UNNAMED PRESSURE
  ↓ coin a name
STABLE HANDLE
  ↓
notes attach
examples attach
contradictions attach
code attaches
stories attach
people reuse it
boundaries become explicit
counterexamples accumulate
meaning changes
  ↓
RELATIONAL FIELD AROUND NAME THICKENS
```

The name did not secretly contain all of that future material.

It provided a stable coordination point around which the material could become attributable.

Candidate term:

> **ADDRESSABLE ATTRACTOR**

Use carefully.

This is a project-local structural metaphor, not a claim that proper names are dynamical attractors in the mathematical sense.

The crucial distinction is:

```text
NAME AS CONTAINER
NO

NAME AS STABLE ADDRESS / COORDINATION POINT
YES, SOMETIMES

NAME AS FUTURE ATTRACTOR FOR RELATION
CANDIDATE — TEST IT
```

# THE TITLE-ONLY DISCOVERY NOW LOOKS DIFFERENT

The title scan that triggered this slice should not be promoted into evidence for an organism.

It is a **discovery trace**.

But it suggests a clean experiment.

Daily Slice titles are themselves names assigned to research events.

Each title compresses some human judgment about what mattered at that cut.

Later, those titles can be read again without the bodies and still produce candidate structure.

So ask:

> **How much formation history survives in the names alone?**

That is no longer a poetic question.

It can fail.

Input only the Slice titles.

Hide bodies, dates, summaries, project memory, and prior interpretations.

```text

```

Then reveal chronology and bodies only after the blind result is frozen.

## `TITLE-SHUFFLE-001`

Randomize title order while preserving the same title set.

If the developmental story appears equally strong under arbitrary order, chronology is probably being supplied by the analyst.

## `ALIAS-001`

One attributable object, multiple names.

Test what information remains stable and what projections change.

```text
SAME REFERENT
DIFFERENT NAME-FORM
```

## `HOMONYM-001`

Same name-form, different referents.

Test whether the system silently merges them.

```text
SAME NAME-FORM
DIFFERENT REFERENT
```

## `RENAME-001`

Rename a live project or bounded concept while preserving its source history.

Measure:

```text
retrieval changes
new associations
lost associations
human comprehension
agent interpretation
source history unchanged?
```

## `PRENAME-001`

Freeze an unnamed concept cluster.

Then coin a name before implementation exists.

Prospectively track which later decisions were already present before naming and which appeared only after the name entered circulation.

This is the direct test of the **addressable attractor** hypothesis.

## `NAME-AUTHORITY-NULL`

Correctly naming an object must grant zero additional authority over it.

```text
CAN NAME
!=
CAN CHANGE
```

# BRIDGE LEDGER

## Documented philosophical / linguistic neighbor

Proper names are a major case in theories of reference; descriptivist and non-descriptivist accounts disagree over whether reference is mediated by descriptive content.

**Bridge type:** scholarly background / boring control.

## Documented cognitive neighbor

Jeshion argues that proper names can mark individuality and operate with mental files used to organize singular thought, including thought about remote or not-yet-existent individuals.

**Bridge type:** scholarly interpretation with cognitive evidence discussion.

## Direct counterexample to naming omnipotence

At least one cross-linguistic taste experiment found no evidence that the tested label differences changed taste perception.

**Bridge type:** empirical null against universal linguistic magic.

## Shakespeare

*Romeo and Juliet* separates the person from the inherited family name while simultaneously showing the social consequences attached to that name.

**Bridge type:** literary structural comparator, not empirical proof of naming mechanisms.

## Static Collective Name work

`THE NAME IS NOT A PASSWORD`, Tetragrammaton continuity, the Name-of-Jesus crucibles, attributable transformation, and typed constitutional projection all independently pressure different non-collapse boundaries around naming.

**Bridge type:** project-owned formation ancestry / internal convergence.

## Addressable attractor

A coined name becomes a stable node around which later information and action accumulate.

**Bridge type:** inference / project-local formal metaphor.

Not yet promoted.

# NEW PREDICTIONS

If the survivor is useful, several things should become observable.

### P1 — names improve re-entry without preserving the whole world

A good title should let a later reader recover useful neighboring structure from far less information than the full source body.

### P2 — renaming should alter projection more than provenance

Changing the name may change associations, retrieval, interpretation, and future proposals while leaving the object's attributable past untouched.

### P3 — names coined prospectively can constrain later development

If an early project name functions as an addressable attractor, later work should cluster around some affordances of the name more than matched unnamed/control clusters do.

This must be measured prospectively. Retrospective fit is too cheap.

### P4 — same-form collisions should be dangerous

Two independent objects with the same name should produce merge errors unless referent scope is preserved.

### P5 — title chronology should matter if the ontogeny is real

A blinded model should recover stronger coherent prerequisite structure from true chronological title order than from shuffled controls.

### P6 — the name should never mint authority

No successful referent resolution should silently confer mutation, admission, canonization, or consequence rights.

# RESIDUAL WEIRDNESS

The weirdest survivor is not that names contain secret power.

It is almost the inverse.

A very small carrier can remain almost ridiculously underdetermined while becoming the center of a huge attributable field.

```text
small word
+
long-lived referent relation
+
community reuse
+
formation history
+
future action
=
relational density far larger than carrier
```

That is why asking “what is **in** the name?” may mislead us.

Much of what matters may not be inside the word at all.

It may be in the lawful relations by which the word keeps finding, gathering, and re-opening a world.

The same correction already appeared with `022100`:

> **The carrier does not carry the world.**

Now the naming version becomes:

> **The name does not contain the world. It can keep a place open where the world remains addressable.**

And the Shakespeare version becomes:

> **The rose keeps its smell. Verona keeps its graph.**

Both matter.
