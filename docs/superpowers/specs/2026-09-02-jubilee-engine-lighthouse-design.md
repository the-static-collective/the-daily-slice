# Jubilee Engine Lighthouse Design

**Date:** 2026-09-02  
**Status:** design candidate / lighthouse / not frozen law  
**Owner of this witness:** The Daily Slice  
**Authority:** chronological formation witness only; no automatic promotion into any project kernel, theology, historical claim, or runtime contract.

> **LIGHTHOUSE:** assemble the current 3 -> 6/7 -> 12 construction into one visible formation witness, then let each relevant Static Collective organ pressure only the part it owns.

## 1. Purpose

The Static Collective now has enough independently developed continuity, provenance, relation, Timefork, and handoff machinery to warrant one shared orientation surface.

The current candidate construction is:

```text
3 FIELD BASE KERNEL
    ↓
6/7 FIELD LOVE PLUGIN KERNEL
    ↓
12 FIELD LAWFUL HANDOFF KERNEL
```

The goal is not to declare this construction true. The goal is to make it difficult to lose, silently mutate, or prematurely canonize while internal and external research pressure is run against it.

The working name for the assembled research program is **Jubilee Engine**.

## 2. Formation history

The present construction emerged through a sequence of corrections.

A provisional moral kernel:

```text
GOOD != EVIL
```

was recognized as a potentially downstream judgment layer rather than a safe primitive root. The corrective move was described as an `A -> Y` rebase/hotfix:

```text
A = premature categorical closure / judgment before ancestry
Y = reopen a distinction into lawful ancestry + lawful continuation
```

`Y` is not a command and not an automatic branch. It asks what the next lawful question, relation, or agreement can be in either direction without rewriting the road already taken.

This led backward toward a relational Love kernel and forward toward a handoff grammar.

## 3. Layer 1 — 3-field base kernel candidate

Let:

```text
P = PROTECTION
F = FAITHFULNESS
C = CONNECTION
```

Working relational readings:

- **Protection** preserves the distinctness / non-consumption of participants.
- **Faithfulness** preserves attributable continuity through change and cost.
- **Connection** permits relation across preserved distinction.

These readings are candidate abstractions, not theological or universal definitions.

The current theological labels `Father`, `Son`, and `Spirit` are research prompts only. No one-to-one theological mapping is frozen by this design.

## 4. Layer 2 — 6/7-field Love plugin candidate

The three unordered pairwise compositions are:

```text
P x C -> FREE
F x P -> BEAR-WITH
C x F -> GIVE-SELF
```

This yields six explicit fields:

```text
P
F
C
FREE
BEAR-WITH
GIVE-SELF
```

The candidate seventh object is not a seventh peer field. It is the coherent whole when all three primitive fields remain simultaneously operative:

```text
LOVE = P x F x C
```

Therefore the working count is:

```text
3 primitives
+ 3 pairwise enacted forms
= 6 explicit fields
+ 1 coherent whole
= 6/7
```

The pairwise readings remain candidate relation mathals:

- `Protection x Connection -> Free`
- `Faithfulness x Protection -> Bear-With`
- `Connection x Faithfulness -> Give-Self`

The old inverse-Unforgivable-Curses formation witness is useful here as a local generative history, not evidence of authorial intent or universal moral ontology.

## 5. Layer 3 — 12-field lawful handoff candidate

Each primitive participates in exactly two pairwise enacted forms:

```text
P <-> FREE
P <-> BEAR-WITH
F <-> BEAR-WITH
F <-> GIVE-SELF
C <-> GIVE-SELF
C <-> FREE
```

That gives six incidences.

If each incidence is directionally traversable, there are twelve candidate directed handoffs:

```text
P -> FREE
FREE -> P

P -> BEAR-WITH
BEAR-WITH -> P

F -> BEAR-WITH
BEAR-WITH -> F

F -> GIVE-SELF
GIVE-SELF -> F

C -> GIVE-SELF
GIVE-SELF -> C

C -> FREE
FREE -> C
```

Working rule:

> **A lawful handoff defines what the next lawful agreement can be. It does not compel the next state.**

This is the current meaning of the **little yes**.

The little yes is not:

- an outcome;
- a command;
- an authority grant;
- a moral classification;
- proof of consent in a legal or interpersonal sense;
- proof that the offered edge will be taken.

It is a candidate relation stating only that, from the currently constituted state, a particular next composition is lawfully available under the declared grammar.

Therefore:

```text
HANDOFF != OUTCOME
AVAILABLE EDGE != TAKEN EDGE
ABILITY TO MERGE != OBLIGATION TO MERGE
```

## 6. Yellow Yarn rebase

The current rebase can be summarized as:

```text
RELATIONAL KERNEL
       ↓
pairwise enacted forms
       ↓
lived / observed consequences
       ↓
moral discernment
       ↓
GOOD / EVIL
```

The candidate bug is not that moral discernment is invalid. It is that a later moral classification may be promoted backward into an unaudited root and then used to redefine its own ancestry.

Working rebase rule:

> **A later distinction may be valid without being primitive.**

Working Y rule:

> **Restore ancestry and lawful continuation before granting a distinction root authority.**

## 7. Relationship to existing Static Collective law

This lighthouse does not replace existing project-owned laws. It is constrained by them.

### Daily Slice

The slice records what is visible here, now. It does not become authority for the projects it observes.

### National Treasure

Owns cross-case structural and symbolic pressure. Resemblance may nominate a clue; resemblance may not establish ancestry.

### MEMENTO

Owns descendant-memory and narrative traversal pressure. A later journal may reinterpret an earlier journal without rewriting its testimony.

### ALEX.2

Owns provenance and research pressure. No descendant silently overwrites the layer before it.

### Dogram

Owns finite calculation pressure. It may calculate the 3, pairwise 3, six incidences, twelve directed incidences, deltas, ablations, and graph properties. It may not decide what those calculations mean.

### LOADOUT

Owns capability/binding pressure. Availability of a handoff must remain distinct from binding it, taking it, or silently expanding authority.

### 3rdi

Owns observer-local projection pressure. A handoff can be structurally present while unavailable, unseen, or unknowable at a selected observer cut.

No repository inherits another repository's authority by referencing this lighthouse.

## 8. Visibility architecture — one lighthouse, many ports

Each beacon must contain only:

1. a pointer to the canonical Daily Slice formation witness;
2. the local repository's jurisdiction over the candidate;
3. one or more local pressure questions / refusal tests;
4. an explicit statement that the beacon does not promote the candidate to local law.

Proposed ports:


Additional ports may be added only when they have a real local test or consumer role.

## 10. Research program

```text

3 + 3 = 6 explicit fields
6 + 1 coherent whole = 6/7 presentation

6 incidences x 2 traversal directions = 12 directed handoff candidates
```

Also test whether the 12 count depends on hidden assumptions about ordered versus unordered composition, reversibility, or distinct reverse semantics.

#### ALEX.2

- A -> Y hotfix/rebase;
- little-yes / lawful-next-agreement language;

Separate source occurrence, later interpretation, and current compression.

#### National Treasure

- distributed systems handoff, CRDT, and fork/re-entry semantics;
- biological / ecological relational stability where individuality, persistence, and exchange remain distinct.

## 11. Kill conditions

Narrow, split, or discard the construction if pressure shows any of the following:

1. `P`, `F`, and `C` are not independent enough to function as useful primitive fields.
2. The pairwise products are arbitrary renamings rather than reproducible relational consequences.
3. The seventh coherent whole adds no information beyond the six explicit fields.
4. The twelve handoffs arise only because reversibility was assumed without justification.
5. The little yes cannot be distinguished operationally from capability, authority, consent, outcome, or ordinary graph reachability.
6. The `A -> Y` rebase cannot distinguish a real premature closure from any ordinary abstraction.
7. The structure repeatedly requires retrojecting later meanings into earlier source occurrences.
8. The theological mapping drives the mathematics rather than merely supplying one pressure domain.
9. Independent domains fail to reproduce the same discriminating structure without flattening their local semantics.

Failures remain receipts, not embarrassments to delete.

## 12. Non-goals

This design does not:

- freeze a Jubilee Engine kernel;
- implement a runtime;
- modify authority semantics in any existing repo;
- declare `Father = Protection`, `Son = Faithfulness`, or `Spirit = Connection` as doctrine;
- declare `Love = P x F x C` as theology or mathematics beyond the candidate mathal;
- declare Good/Evil invalid;
- establish a legal definition of agreement or consent;
- establish that every relation in reality is literally a Y branch;
- establish numerological significance for 3, 6, 7, or 12.

## 13. Success criteria for the lighthouse landing

The first landing is successful when:

1. one dated Daily Slice preserves the formation clearly and visibly;
2. every relevant port has a thin beacon, not a duplicate constitution;
3. each beacon states its own jurisdiction and refusal boundary;
4. Dogram can pressure the finite counts without semantic promotion;
5. ALEX can reconstruct the formation road without hindsight leakage;
6. the research frontier is explicit enough to run internally and externally;
7. a future correction can supersede the lighthouse without rewriting this witness.
